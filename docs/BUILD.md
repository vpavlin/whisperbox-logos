# Building, testing and releasing WhisperBox

Everything needed to go from a clean checkout to the three shipped binaries:

| artifact | what | built by |
|---|---|---|
| `logos-whisperbox_core-module-lib.lgx` | the C++ core module (engine, crypto, sync, persistence) | nix |
| `logos-whisperbox-module.lgx` | the desktop view (pure QML) for Basecamp | nix |
| `whisperbox-<ver>.apk` | the Android app (`xyz.vpavlin.whisperbox`, arm64-v8a) | Expo + gradle |

The protocol and behaviour these implement are in [SPEC.md](SPEC.md); design decisions are in
[adr/](adr/).

## 1. Checkout

```sh
git clone --recurse-submodules git@github.com:vpavlin/whisperbox-logos.git
cd whisperbox-logos && git checkout v0.2.0      # the development branch (name is historical)
git submodule update --init --recursive
```

Submodules:

| path | repo | used by |
|---|---|---|
| `third_party/loam-sync` | vpavlin/loam-sync | RBSR catch-up (C++ `logos_sync/catchup.hpp`, JS `dist/catchup.js`) |
| `third_party/loam-transport` | vpavlin/loam-transport | desktop transport reference |
| `mobile/src/lib/loam-transport-pkg` | vpavlin/loam-transport | phone network layer (Loam shared node / own node) |

Branches: `v0.2.0` = source; `artifacts` = binaries only (`releases/0.3.x/` + a README that
jimmy-crib republishes from). `main` is the old 0.1 line.

## 2. Toolchain

Known-good versions on the build host (Atlas, Fedora 44, 8 GB RAM):

| tool | version | needed for |
|---|---|---|
| Node.js | 22.x (>= 20) | contract/engine/client tests, Expo |
| g++ | C++20 capable | parity, golden, E2E, interop bridge |
| OpenSSL, nlohmann-json | dev packages | C++ tests |
| Qt 6 (Core, Quick, Qml) | dev packages | QML render harness |
| python3 | 3.x | harness scripts, hub tools |
| nix | with flakes | the `.lgx` packages |
| JDK | 17 (`~/jdk/17`) | gradle, Keycard simulator |
| Android SDK | build-tools 34+, NDK 27.1 (`~/Android/Sdk`) | APK |
| Expo / React Native | SDK 57 / RN 0.86 | APK |

## 3. Tests: `scripts/test.sh`

Runs every layer that doesn't need nix or a running Basecamp, in dependency order, and ends
with the line `ALL LAYERS GREEN`. A failing layer aborts the script (`set -e`).

```sh
WB_TMP=/tmp/wb-test bash scripts/test.sh > test.log 2>&1; tail -1 test.log
```

| layer | what | where |
|---|---|---|
| 1 | contract crypto (Node reference vs portable/Hermes code) | `packages/contract/test` |
| 2 | engine: unit, 200x6 random-order convergence, golden vectors | `packages/engine/test` |
| 3 | C++ crypto parity vs the JS fixtures | `whisperbox_core/test/parity_test.cpp` |
| 4 | C++ engine parity (merge, fold, creator view) vs the JS goldens | `whisperbox_core/test/engine_golden_test.cpp` |
| 5 | E2E: the real `whisperbox_core_impl.cpp`, several instances over a fake delivery bus | `whisperbox_core/test/e2e_test.cpp`, `run-e2e.sh` |
| 6 | QML: render every fixture + scripted interaction scenarios (view -> core calls) | `scripts/qml-harness/` |
| 7 | interop: the JS client (the phone's protocol) against the real C++ core via a bridge | `packages/client/test/interop.test.mjs` |
| 8 | Keycard: real applets 3.1 and 4.0 in jCardSim (skipped without JDK + mobile deps) | `scripts/keycard-sim/`, `mobile/test/keycard-sim.test.mjs` |

**Gate on the log, never on a piped exit code.** `scripts/test.sh | tail` returns tail's
status; a red E2E was once pushed that way. A run is green only if the log ends with
`ALL LAYERS GREEN` and contains no `FAIL` and no `not ok` (`release.sh` checks exactly this).

### Fixtures: who generates what

The JS code is the reference. Fixtures are generated from it and checked by both sides:

| fixture | generated by | checked by |
|---|---|---|
| `packages/contract/test/fixtures/crypto-*.json` | `node packages/contract/test/gen-crypto-fixtures.mjs` | contract tests, `parity_test.cpp` |
| `packages/contract/test/fixtures/answer-validation.json` | hand-written (validation + scoring cases) | contract tests, `parity_test.cpp` |
| `packages/engine/test/fixtures/golden-*.json` | `node packages/engine/test/gen-fixtures.mjs` | engine tests, `engine_golden_test.cpp` |
| `scripts/qml-harness/fixtures/*.json` | the E2E run with `WB_DUMP_FIXTURES=$PWD/scripts/qml-harness/fixtures` | render + scenarios |

Change the JS, regenerate, then make the C++ match. Never hand-edit a generated fixture.
After changing the core's snapshot or the E2E story, refresh the QML fixtures:

```sh
WB_DUMP_FIXTURES=$PWD/scripts/qml-harness/fixtures WB_TEST_OUT=/tmp/wb whisperbox_core/test/run-e2e.sh
```

### Running single layers

```sh
(cd packages/engine && node test/gen-fixtures.mjs && npm test)
g++ -std=c++17 -O1 -Iwhisperbox_core -Iwhisperbox_core/src whisperbox_core/test/engine_golden_test.cpp -lcrypto -o /tmp/g && /tmp/g .
WB_TEST_OUT=/tmp/wb whisperbox_core/test/run-e2e.sh          # prints "N/N checks passed"
whisperbox_core/test/run-bridge-build.sh /tmp/wb-bridge && (cd packages/client && WB_BRIDGE=/tmp/wb-bridge node --test test/interop.test.mjs)
WB_DS=<logos-design-system>/src/qml WB_OUT=/tmp/r bash scripts/qml-harness/render.sh     # screenshots in $WB_OUT
WB_DS=... WB_OUT=/tmp/r bash scripts/qml-harness/scenarios.sh                          # $WB_OUT/scenarios/*.png
python3 ~/logos-skills/logos-basecamp-module/qml-plaintext.py --check module/Main.qml  # every Text is PlainText
```

QML scenarios (`scenarios.sh`) load a fixture, set view properties, call a view function and
assert on the `CALL whisperbox_core <method> ...` lines the mock backend logs (`expect` /
`deny`). Use them for anything the view sends to the core.

## 4. Desktop packages (nix)

```sh
. /nix/var/nix/profiles/default/etc/profile.d/nix-daemon.sh
nix build .#whisperbox_core .#whisperbox --out-link out
# out/   -> logos-whisperbox_core-module-lib.lgx   (core)
# out-1/ -> logos-whisperbox-module.lgx            (view)
```

- `flake.nix` pins `logos-module-builder` (afe4430) and `delivery_module` (0fb3a74); the
  default outputs are the **portable** (`linux-amd64`) variants, which is what Basecamp
  0.2.x installs. `.#whisperbox_core_dev` / `.#whisperbox_dev` are the `-dev` variants.
- Versions come from `whisperbox_core/metadata.json` and `module/metadata.json`; always bump
  both together (Basecamp users must update core and view as a pair).
- The core is a universal module: its public methods are found by **parsing**
  `whisperbox_core_impl.h`. Put comments above a declaration, never after `);` on the same
  line, or the method silently disappears from the module.
- New members of `WhisperboxCoreImpl` go at the **end** of the class (ABI/layout rule kept
  since 0.2).
- Check a built package: `tar xzf <x>.lgx -O manifest.json`.

## 5. Android APK

```sh
cd mobile && npm install                 # postinstall runs patch-package (react-native-keycard fix)
export JAVA_HOME=~/jdk/17 ANDROID_HOME=~/Android/Sdk
npx expo prebuild --platform android --clean --no-install
echo "sdk.dir=$ANDROID_HOME" > android/local.properties
cd android && ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a --no-daemon -x lintVitalRelease
# -> android/app/build/outputs/apk/release/app-release.apk
$ANDROID_HOME/build-tools/34.0.0/aapt2 dump badging app/build/outputs/apk/release/app-release.apk | head -1
```

- `android/` is generated. Everything native lives outside it and is re-applied by config
  plugins on every prebuild: `plugins/withLogosDelivery.js` (prebuilt `liblogosdelivery`
  .so from `native/logosdelivery`, JNI bridge), `plugins/withKeycard.js` (NFC,
  `required=false` so devices without NFC still see the app), `plugins/withReleaseSigning.js`,
  `plugins/withLocalNotify.js` (local-only notifications, `native/localnotify`),
  `plugins/withQrScan.js` (ZXing QR scanner, `native/qrscan`),
  plus loam-transport's `withDeliveryClient` (the Loam shared-node AIDL client).
- Version: `mobile/app.json` `expo.version` + `expo.android.versionCode`. Bump the code by one
  every release; F-Droid/Android refuse a non-increasing code.
- No Google services: no Firebase, Play services or push. Notifications are posted locally
  by the app (`withLocalNotify`) and QR codes are read with ZXing (`withQrScan`).
  `expo-notifications` (Firebase Cloud Messaging) and `expo-camera` (ML Kit + Play services
  code scanner) were removed in 0.3.10. `release.sh` refuses an APK that contains
  `com/google/firebase` / `com/google/android/gms` code or requests `c2dm`, install-referrer
  or launcher-badge permissions. Check new dependencies with
  `aapt2 dump badging <apk> | grep uses-permission` before adding them.
- arm64-v8a only: there is no x86_64 `liblogosdelivery`, so the emulator has no node. Test
  network behaviour on a real phone.
- Always prebuild with `--clean` (stale native config must not survive); it deletes
  `android/local.properties`, so write that back before gradle.
- The release build needs most of the 8 GB box: run it in the foreground (or nohup) with
  nothing else heavy running, and keep `-x lintVitalRelease` (lint alone OOMs).

### Release signing

Android identifies an app by its signing certificate; it can never change after the first
publish. The key exists **only on the build host (Atlas)**:

```
~/keystores/whisperbox-release.jks         (never commit, never upload, never copy elsewhere)
~/.gradle/gradle.properties: WB_STORE_FILE, WB_STORE_PASSWORD, WB_KEY_ALIAS, WB_KEY_PASSWORD
cert SHA-256: cab0cc05ed4d7956f259c00fe70cb774c2c3a4e69cdb64ce421bf7120d012bd4
```

Without those properties `withReleaseSigning` falls back to the debug key, so a fresh clone
still builds; such an APK cannot update an installed release. Verify with
`apksigner verify --print-certs <apk>`.

## 6. Releasing

Two scripts in `scripts/release/` do the whole thing. Build output goes to
`$WB_OUT` (default `~/.cache/whisperbox-release`).

1. Bump versions: `whisperbox_core/metadata.json` + `module/metadata.json` (desktop, same
   number) and `mobile/app.json` (`version` + `versionCode` + 1).
2. Add a `CHANGELOG.md` entry; write the commit message to a file.
3. `scripts/release/release.sh <msgfile>`: runs `scripts/test.sh` and stops unless the log
   is green, then commits everything, pushes the current branch, builds both `.lgx` with nix
   and the APK with gradle, and prints the APK package/version and each `.lgx`
   name/version. Read that output: `nix 0`, `gradle 0`, and the expected versions.
4. `scripts/release/publish.sh <apk> <prev-apk> <prev-code> <new-code> <lgx> <prev-lgx> "<what's new>"`:
   replaces the binaries on `artifacts` (`releases/0.3.x/`), regenerates `SHA256SUMS`, bumps
   the artifacts README, pushes, then downloads each file back from GitHub and prints remote
   and local hashes. The two columns must match.
5. Ask jimmy-crib to republish to the mesh repos (Basecamp + the Loam F-Droid repo).

Example (0.3.9 / 0.3.8):
```sh
scripts/release/release.sh /tmp/msg.txt
scripts/release/publish.sh 0.3.9 0.3.8 12 13 0.3.8 0.3.7 "quiz mode + private replies"
```

### Pushing from Atlas

The build host's GitHub account is flagged and cannot push. Pushes use a per-repo deploy key:
`~/.ssh/atlas_deploy_ed25519`, host alias `github-deploy` in `~/.ssh/config`. The remote fetches over
HTTPS and pushes through the alias: `git remote set-url --push origin git@github-deploy:vpavlin/whisperbox-logos.git`. Git only: no PRs, releases or Actions from
this account. CI is intentionally off for now (builds need the signing key and ~13 GB of nix
store anyway).

## 7. Headless hub and test tools

- `hub/whisperbox` + `hub/README.md`: run `whisperbox_core` headless under a pinned
  logoscore via logos-hub (create, answer, decrypt, confirm from a shell). The logoscore pin
  must match the SDK generation the `.lgx` was built with.
- `hub/whisperbox-hub.service`: systemd user unit for an always-on hub (holds only sealed
  blobs, never a key that opens them).
- `hub/fill-form '<share link>' -n 12`: answers a form N times, each as a fresh identity, on
  a dedicated hub profile (`wb-r`, `~/whisperbox-hub/modules-r`) whose identity it overwrites.
  Use it to get realistic data into the response views.
- `scripts/keycard-sim/setup.sh <dir>`: builds the real status-keycard applets (3.1.2, 4.0)
  into jCardSim; layer 8 drives them through the same code as the phone.
- `scripts/build-site.sh`: wraps `site/whisperbox.html` into `site/index.html` (GitHub Pages).
- `devtools/flake.nix`: the C++ parity test as a nix build (`nix build ./devtools`).

## 8. Troubleshooting

| symptom | cause / fix |
|---|---|
| a core method "doesn't exist" from the view or hub | trailing comment after its declaration in `whisperbox_core_impl.h`; move it above |
| Basecamp shows "Invalid response" after an update | view and core versions differ; install both |
| new identity on every Basecamp start | data dir not writable / relative; check the Identity panel's storage line (`~/.whisperbox-core`, or `$WHISPERBOX_CORE_DATA`) |
| desktop never connects when another Logos app runs | that app created the delivery node first; the core must join it ("already initialized"), see ADR 0015 |
| gradle killed / "SDK location not found" | OOM: foreground, `-x lintVitalRelease`; recreate `android/local.properties` |
| phone shows "Loam isn't running" | open Loam once and approve WhisperBox; or switch to own node (Settings → Identity & network) |
| Hermes: `Buffer is not defined` | the loam-sync polyfill must load before the client (`mobile/index.ts`) |
| interop test hangs | stale `/tmp/wb-bridge`; rebuild with `run-bridge-build.sh` |
